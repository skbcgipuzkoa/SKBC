# Next-call filtering and voluntary exam invitations

User-directed scope: upcoming club call filter (summer/winter, not both pooled); personalised selectable emails; exam date before preview/send; voluntary accept/defer with optional message; admin responses; accepted students automatically reserved in editable integrated exam; advance cash payment completes registration outside this new workflow (kids10EUR+5belt=15, adults15+5belt=20).

## Construction plan
- Shared call identity helper and next-call filter in proximos-examenes; keep all-calls option. Actual exam date and call attribution are distinct. January/February normal examinations belong to preceding December; retakes must retain their separate actual date and explicit flag. Do not silently rewrite historical dates or exam eligibility without reliable retake provenance.
- Invitations persisted with migration: authenticated admin creates batch/draft with chosen candidates, configured call, actual exam date, instructions and preview. No email sent on preview, GET, migration or deploy. Explicit send action only. Individually addressed mail using existing Nodemailer configuration and auditable delivery statuses; immutable amount and progression text snapshots.
- Invitation has high-entropy response token, only hash stored; public landing shows own invitation only, GET never accepts/defer. Explicit POST accepts/defer plus bounded optional message; atomic/idempotent response+student enrolment in same RPC. Wrong/expired/revoked token fails safely. Decline means this call deferred, not enrolment in unrelated next exam.
- Accepted unpaid students are reserved in integrated exam, clearly pending payment; no grade promotion/result registration by invitation. Admin payment recording marks completed financial registration; amount15kids/20adult, fees split. Admin may edit actual exam date/event details via existing or focused new controls. Admin responses surfaced in invitations/exam list.
- Plain+HTML email: personal name, group/targetgrade/call+actual date, honest reason: favorable projection vs preparation-needs-refuerzo (never promise all will qualify); current deficits, teacher final review, voluntary right not obligation, fees/prepayment, button/link to accept or defer and message. No fabricated location/bank information; optional instructions supplied by admin.
- Reuse existing integrated-exam snapshot generation; avoid creating fake passed exams or unaccepted student rows. Build empty planned event snapshot safely, enrol accepted invitee atomically. Prevent duplicate invitations/student records, concurrent accept/send/payment and false success after partial delivery.
- Scoped ownership backend/invitationSQL, UI, call logic in parallel. Tests use synthetic data only; regressions for auth/tokensecurity/GET no mutation/duplicates/fees/callsJanFebretakes/paymentgate/realactions/outbound send fake transport only. Build+independent security/code review, migration apply through authorised existing credentials if available, deploy+browserpreview; never send real emails during tests.

User steering: NO new payment tracking, ledger, paid status, payment actions or finalization gate. Club collects cash in hand and uses its existing control. Keep fees (10+5 kids,15+5 adults) and advance-payment condition in email/public acceptance only. Acceptance reserves the student, never marks payment made.
