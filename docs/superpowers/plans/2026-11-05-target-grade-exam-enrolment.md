# One invitation examination per call, programme and target grade

User requests that students accepting the same target grade join the same exam, with the target-grade syllabus and teacher-editable items.

- Current finding: target-grade curriculum generation and add/remove editing exist, but invitation preparation groups the whole adult/child class within one batch and does not reuse grade groups across batches.
- Prepare a canonical exam per call month, programme and target grade. Reuse it across invitation batches before the first acceptance too, so teacher edits cannot be lost when a later invitee responds first. Acceptance enrols into that same exam atomically and idempotently; different target grades/programmes remain separate.
- Reuse existing target-grade curriculum builders. Adults receive the target grade's content; children's existing progression through that target remains intact, never including higher stages. Subsequent acceptance must never regenerate or overwrite manual additions, removals, weights, notes or examiner setup.
- Reused exams keep their confirmed/pending-day state. Do not silently change the date of an existing group. Started or completed exams and academic history remain untouched. Cleanup must never delete a reused group.
- Safely reconcile only unstarted existing invitation groups where grouping and syllabus scope are known, preserving invitation tokens/IDs, approvals, responses and accepted reservations. Run read-only diagnostics and synthetic SQL rollback regressions before reconciling production records. No real responses, emails, exam results or grades are generated by tests.
- Preserve already-shared examiner links through parent/clone aliases, with the same assigned grades and revocation checks. A one-grade link redirects; a multi-grade link offers only its authorised child exams. Pending examiner identities and revoked links never gain access.
- Add explicit target-grade labels and links to review the syllabus from the planning response cards and Exámenes. Test same-grade acceptance across batches, different-grade isolation, target syllabus, repeated acceptance, editable-template preservation and all month/date/deferral safeguards. Independent review, migration, build and production deployment follow.
